# Portfolio Building for IT
### Module 09 · Graphics Design · 26–27 1st Sem

---

## Module Overview

A portfolio is the single most important career document an IT professional can have. Unlike a résumé that lists what you did, a portfolio **shows** what you can do. This module walks students through building a professional IT portfolio from scratch — what to include, how to structure and design it, where to publish it, and how to present it.

---

## Learning Objectives

By the end of this module, students will be able to:

1. Explain what an IT portfolio is and why it matters in the job market.
2. Identify the key components that belong in an IT portfolio.
3. Curate and present their own projects with clarity and context.
4. Apply visual design principles to structure a portfolio layout.
5. Publish a working portfolio using a free platform.
6. Present their portfolio confidently to a panel or employer.

## Part 1 — What Is a Portfolio and Why It Matters
*Slides 1–4*

### 1.1 The Portfolio vs. the Résumé
A résumé tells. A portfolio proves. Employers in IT — especially in development, UI/UX, data, and QA — increasingly expect to see work, not just credentials. A portfolio answers the question every hiring manager has: *"Can this person actually do the job?"*

### 1.2 Who Needs a Portfolio in IT?
- **Web & Software Developers** — source code, live demos, GitHub repos
- **UI/UX Designers** — wireframes, prototypes, case studies
- **Data Analysts** — dashboards, reports, visualizations
- **QA Engineers** — test plans, bug reports, automation scripts
- **Network / Systems Admins** — lab setups, documentation, certifications
- **IT Students** — academic projects, activities, personal builds

### 1.3 What Employers Actually Look For
Employers scan a portfolio for three things:
1. **Evidence of skill** — real work, not just descriptions
2. **Problem-solving process** — how you think, not just what you built
3. **Communication** — can you explain your work clearly to a non-technical person?

### 1.4 Portfolio Formats
| Format | Best For | Examples |
|---|---|---|
| Website | All IT roles | GitHub Pages, Notion, Wix |
| PDF Deck | Job applications, email | Canva, PowerPoint export |
| GitHub Profile | Developers | README, pinned repos |
| Behance / Dribbble | UI/UX, Graphic Design | Case study posts |

## Part 2 — What to Include
*Slides 5–9*

### 2.1 The 6 Core Sections of an IT Portfolio

1. **About / Introduction** — Who you are, what you do, what you are looking for. Keep it to 3–4 sentences. Write it like a human, not a job posting.

2. **Skills** — List your technical skills grouped by category (Languages, Frameworks, Tools, Platforms). Do not list skills you cannot demonstrate.

3. **Projects** — The heart of the portfolio. Each project entry should include:
   - Project title and brief description (1–2 sentences)
   - The problem it solved
   - Your role and the tools/technologies used
   - A screenshot, demo link, or GitHub link
   - What you learned or would improve

4. **Work Experience / Internship** — Include even part-time or OJT experience. Focus on what you contributed, not just your job title.

5. **Education & Certifications** — Degree, school, year. Add relevant certifications (e.g., AWS, Google, Cisco, Meta).

6. **Contact** — Email, LinkedIn, GitHub. Make it easy to reach you.

### 2.2 How Many Projects Should You Include?
- **Students / Fresh Graduates:** 3–5 projects minimum
- **Quality over quantity** — one well-documented project beats five undescribed ones
- Include at least one project where you can explain every decision you made

### 2.3 What NOT to Include
- Projects you cannot explain or defend
- Placeholder or template work presented as original
- Outdated or broken links
- A photo that looks unprofessional
- Skills listed at "expert" level that you cannot demonstrate

### 2.4 Writing a Project Case Study
Every project entry should answer these five questions:

1. **What was the problem?** — Context and goal
2. **What did you build?** — Brief description of the solution
3. **How did you build it?** — Tools, stack, process
4. **What was the result?** — Outcome, metrics, or feedback
5. **What did you learn?** — Honest reflection

### 2.5 GitHub as a Portfolio Tool
For developers, a well-maintained GitHub profile is a portfolio in itself.

- Pin your 4–6 best repositories
- Write a clear `README.md` for every pinned repo — include what it does, how to run it, and a screenshot
- Keep commit history clean and consistent
- Add a profile `README.md` with a short bio and links

## Part 3 — Design and Structure
*Slides 10–14*

### 3.1 Visual Hierarchy in a Portfolio
Apply the same visual hierarchy principles from the Hierarchy module:

- **Name / Title** — largest, most prominent element on the page
- **Section headings** — clearly separated, consistent size
- **Project titles** — bold, scannable
- **Body text** — readable, not too small (minimum 14px on screen)
- **Labels / tags** — small, muted, supporting role

### 3.2 Layout Principles
- Use a **grid** — align everything to a consistent column structure
- **Whitespace is not wasted space** — it gives the eye room to rest and makes content feel premium
- Limit to **2 fonts maximum** — one for headings, one for body
- Use **1–2 accent colors** — consistent with your personal brand

### 3.3 Color and Tone
Your portfolio's color palette communicates your personality before the reader reads a single word.

| Palette Style | Impression | Good For |
|---|---|---|
| Dark + neon accent | Technical, modern | Developers, data |
| White + bold color | Clean, confident | UI/UX, design |
| Neutral + muted | Professional, calm | Business, systems |
| Colorful, playful | Creative, energetic | Front-end, media |

### 3.4 Mobile Responsiveness
More than 50% of recruiters view portfolios on mobile. Your portfolio must:
- Stack columns to single column on small screens
- Keep tap targets large enough (minimum 44px)
- Load fast — compress images, avoid heavy animations

### 3.5 Common Design Mistakes to Avoid
- **Wall of text** — break content into short paragraphs and bullet points
- **Too many colors** — pick a palette and stick to it
- **No contrast** — light grey text on white background is unreadable
- **Inconsistent spacing** — use consistent padding and margins throughout
- **Autoplay music or video** — never

## Part 4 — Publishing and Platforms
*Slides 15–17*

### 4.1 Free Portfolio Platforms Compared

| Platform | Best For | Custom Domain | Coding Required |
|---|---|---|---|
| GitHub Pages | Developers | Yes (free) | Yes |
| Notion | All roles | Paid only | No |
| Wix | Non-developers | Paid | No |
| Canva Website | Design-focused | Paid | No |
| Behance | UI/UX, Graphic Design | No | No |
| Carrd | Simple one-page | Paid | No |

### 4.2 Recommended Stack for IT Students
For students who can code, the recommended approach is:

1. Build with **HTML + CSS + JavaScript** (or a framework like React)
2. Host on **GitHub Pages** — free, fast, version-controlled
3. Use a custom domain from **Namecheap** or **Cloudflare** (~₱500/year)

This approach itself demonstrates technical skill to employers.

### 4.3 Keeping Your Portfolio Updated
A portfolio is never finished. Set a reminder to:
- Add new projects after every major course or internship
- Update your skills list every semester
- Remove outdated or weak projects as better ones replace them
- Check all links are working before sharing

## Part 5 — Activity, Assessment & Summary
*Slides 18–20*

### 5.1 Group Activity — Portfolio Audit

Working individually, students will:

1. Open any IT professional's public portfolio (GitHub, Behance, personal site)
2. Evaluate it using the checklist below
3. Share one strength and one improvement with the class

**Audit Checklist:**
- [ ] Clear introduction — who they are and what they do
- [ ] At least 3 projects with descriptions
- [ ] Each project has a link or screenshot
- [ ] Skills section is present and specific
- [ ] Contact information is easy to find
- [ ] Design is clean and readable on mobile
- [ ] No broken links

### 5.2 Individual Assignment — Build Your Portfolio Draft

**Task:** Create the first draft of your own IT portfolio.

**Requirements:**
- Platform of your choice (GitHub Pages, Notion, Canva, Wix, etc.)
- Must include: About, Skills, at least 2 Projects, Contact
- Each project must have a title, description, tools used, and one screenshot or link
- Submit the live URL or PDF export via the Google Form provided

**Filename (for PDF submissions):** `Portfolio_Surname_Firstname.pdf`

**Deadline:** As announced by the instructor.

### 5.3 Assessment Rubric

| Criteria | Points |
|---|---|
| Completeness — all 4 required sections present | 25 |
| Project documentation — problem, tools, result stated | 25 |
| Design — readable, consistent, visual hierarchy applied | 20 |
| Writing — clear, professional, no placeholder text | 15 |
| Published and accessible (live URL or PDF) | 15 |
| **Total** | **100** |

## Key Takeaways

1. A portfolio is proof of skill — it shows what a résumé can only claim.
2. Quality over quantity — 3 well-documented projects beat 10 undescribed ones.
3. Every project entry must answer: what was the problem, what did you build, and what did you learn.
4. Design matters — apply visual hierarchy, limit colors, and test on mobile.
5. GitHub is a portfolio for developers — keep it clean and documented.
6. A portfolio is never finished — update it after every major project or milestone.
