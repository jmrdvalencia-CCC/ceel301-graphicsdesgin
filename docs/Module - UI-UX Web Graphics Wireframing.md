## PART 1: WHAT IS UI/UX WEB DESIGN? (25 minutes)

### 1.1 Defining the Field

As digital media has expanded, graphic design has extended beyond print and static visuals into interactive, screen-based experiences. *Mrantinkovic et al. (2020)* note that the graphic designer's role in the digital environment now includes understanding how users interact with visual interfaces — not just how those interfaces look.

This has given rise to two closely related but distinct disciplines:

**UI (User Interface) Design** is the practice of designing the visual and interactive elements a user directly engages with on a screen — buttons, menus, forms, icons, typography, and layout.

**UX (User Experience) Design** is the broader practice of shaping the entire experience a person has while interacting with a digital product — how it feels, how easy it is to use, and whether it successfully helps the user achieve their goal.

> **Key Distinction:** UI is what it looks like. UX is how it works and feels. A visually polished interface with poor UX frustrates users. A well-structured UX with poor UI fails to communicate trust or quality. Both are required.

---

### 1.2 UI/UX and Graphic Design — The Relationship

Students who have completed the Design Principles, Visual Hierarchy, and Color Theory modules already understand the foundational language of visual communication. In UI/UX web design, those same principles are applied within a new set of constraints specific to interactive, screen-based media.

| Graphic Design Context | UI/UX Web Design Context |
|---|---|
| Static compositions | Interactive, multi-state layouts |
| Single viewing context | Multiple devices and screen sizes |
| Aesthetic-first decisions | Function-first, aesthetic-second |
| Fixed dimensions | Fluid, responsive grids |
| One-time experience | Repeated, habitual use |

The principles do not change — hierarchy, balance, contrast, and proximity still govern good layout. What changes is the **purpose**: in UI/UX, every design decision must serve the user's task, not just the designer's aesthetic intent.

> **Key Insight:** According to *Mrantinkovic et al. (2020)*, effective digital design is not decoration — it is functional communication. A beautiful web page that confuses the user has failed its primary purpose.

---

### 1.3 What is Wireframing?

A **wireframe** is a low-detail, structural blueprint of a web page or screen. It defines:
- What content appears on the page
- Where each element is positioned
- How the user navigates between pages
- What interactions are available

Wireframing is to web design what thumbnail sketching is to logo design — it is the ideation and planning stage that happens **before** any visual design decisions (color, typography, imagery) are made.

> **Rule:** Never open a design tool before you have a wireframe. Designing without a wireframe is like building a house without a floor plan — the structure is guessed, not planned.

---

### 1.4 The Web Design Process — Where Wireframing Lives

*Mrantinkovic et al. (2020)* describe the design process as a structured sequence of stages, each building on the previous. Wireframing occupies a critical position between strategic thinking and visual execution.

```
Research → Define → Ideate → Wireframe → Prototype → Test → Visual Design → Build
                                  ↑
                          You are here
```

| Stage | What Happens |
|---|---|
| Research | Understand users, goals, and context |
| Define | Identify the problem to solve |
| Ideate | Brainstorm solutions and user flows |
| **Wireframe** | **Sketch the structure and layout** |
| Prototype | Make it interactive (clickable) |
| Test | Validate with real users |
| Visual Design | Apply color, type, and imagery |
| Build | Hand off to developers |

Wireframing sits at the intersection of thinking and making. It is cheap to change a wireframe. It is expensive to change a built interface.

---

### 1.5 Fidelity Levels — Lo-fi, Mid-fi, Hi-fi

**Fidelity** refers to how closely a wireframe resembles the final product. *Mrantinkovic et al. (2020)* identify the progression from rough sketches to refined layouts as a core part of the professional design workflow.

| Fidelity | Description | When Used |
|---|---|---|
| **Lo-fi (Low Fidelity)** | Rough boxes, lines, placeholder text. No styling. | Early ideation, paper sketches |
| **Mid-fi (Medium Fidelity)** | Defined layout, real labels, basic spacing. Grayscale. | After concept is validated |
| **Hi-fi (High Fidelity)** | Near-final layout with real content, fonts, and spacing. | Before visual design handoff |

> This module focuses on **lo-fi paper wireframes** — the fastest and most flexible form of wireframing. Lo-fi wireframes allow designers to explore many layout options quickly without investing time in visual polish that may need to be discarded.

## PART 2: UX THINKING — USER FLOWS & INFORMATION ARCHITECTURE (25 minutes)

### 2.1 Starting with the User

Before drawing a single box, a UX designer must understand who the user is and what they are trying to accomplish. *Mrantinkovic et al. (2020)* emphasize that design decisions made without user understanding are guesses — and guesses produce interfaces that serve the designer, not the audience.

A **user persona** is a representative profile of the target user that guides every design decision.

**Example Persona:**
> **Name:** Maya, 28
> **Context:** Looking for a local coffee shop on her phone during her commute
> **Goal:** Find the menu and opening hours in under 30 seconds
> **Frustration:** Websites that make her scroll past a full-screen hero image before she finds basic information

Every wireframe decision — what goes above the fold, what the primary call to action is, how many clicks to reach key content — should be answerable by referring back to the persona.

---

### 2.2 Information Architecture (IA)

**Information Architecture** is the practice of organizing, structuring, and labeling content so users can find what they need efficiently. It is the structural foundation of any website before a single visual element is designed.

The primary tool for IA is the **sitemap** — a diagram showing every page of a website and how they connect.

**Example Sitemap — Coffee Shop Website:**
```
Home
├── Menu
│   ├── Drinks
│   └── Food
├── About
├── Locations
│   ├── Branch A
│   └── Branch B
├── Events
└── Contact
```

**IA Principles:**

| Principle | What It Means |
|---|---|
| **Hierarchy** | Group related content under clear parent categories |
| **Clarity** | Label navigation with words users actually use — not internal jargon |
| **Depth** | Aim for no more than 3 clicks to reach any page |
| **Consistency** | Navigation must appear in the same place on every page |

---

### 2.3 User Flows

A **user flow** maps the path a specific user takes through a website to complete a specific task. It is more granular than a sitemap — it shows decisions, branches, and outcomes.

**Notation:**
- **Rectangle** — a page or screen
- **Diamond** — a decision point
- **Arrow** — the direction of navigation

**Example User Flow — Online Order:**
```
Landing Page → Menu Page → [Item Selected?]
                                ├── Yes → Cart → Checkout → Confirmation
                                └── No  → Continue Browsing → Menu Page
```

User flows reveal:
- Where users might get lost
- Which pages carry the most navigational weight
- Where drop-off is likely to occur

> **Before wireframing any page, define the user flow it belongs to.** A page without a flow has no context — it is a room with no doors.

---

### 2.4 Content Inventory

Before laying out a page, list every piece of content that needs to appear on it. This is called a **content inventory** — a structured list that prevents designers from building layouts around missing or undefined content.

**Example — Homepage Content Inventory:**

| # | Content Item | Type | Priority |
|---|---|---|---|
| 1 | Brand name + tagline | Text | High |
| 2 | Primary CTA (e.g., "Order Now") | Button | High |
| 3 | Hero image or illustration | Image | Medium |
| 4 | Featured menu items | Cards | Medium |
| 5 | Opening hours | Text | High |
| 6 | Location map | Embed | Medium |
| 7 | Social media links | Icons | Low |
| 8 | Footer navigation | Links | Low |

Priority determines placement — high-priority content goes above the fold (visible without scrolling). Low-priority content goes in the footer or secondary pages.

## PART 3: WIREFRAME ANATOMY (25 minutes)

### 3.1 The Anatomy of a Web Page

Every web page — regardless of industry or visual style — is built from a consistent set of structural regions. *Mrantinkovic et al. (2020)* identify layout structure as one of the core competencies of digital graphic design.

```
┌─────────────────────────────────────┐
│              HEADER                 │  ← Logo + Navigation
├─────────────────────────────────────┤
│                                     │
│              HERO                   │  ← Primary message + CTA
│                                     │
├─────────────────────────────────────┤
│                                     │
│           MAIN CONTENT              │  ← Core page content
│                                     │
├─────────────────────────────────────┤
│           SECONDARY CONTENT         │  ← Supporting info, cards, etc.
├─────────────────────────────────────┤
│              FOOTER                 │  ← Links, legal, contact
└─────────────────────────────────────┘
```

Each region has a defined role. Deviating from this structure requires a strong UX reason — users have learned to expect it, and violating expectations increases cognitive load.

---

### 3.2 Wireframe Components

These are the building blocks used in every wireframe. In lo-fi wireframing, all components are represented as simple geometric shapes — no color, no real images, no styled typography.

| Component | Symbol | Purpose |
|---|---|---|
| **Box** | Rectangle | Any container — image, card, section |
| **X-Box** | Rectangle with diagonal X | Image placeholder |
| **Lines** | Horizontal lines | Text placeholder |
| **Button** | Rounded rectangle with label | CTA or action |
| **Nav bar** | Horizontal strip with labels | Primary navigation |
| **Input field** | Rectangle with underline | Form entry |
| **Checkbox / Radio** | Small square or circle | Selection input |
| **Icon placeholder** | Small circle or square | Icon or avatar |
| **Divider** | Thin horizontal line | Section separator |

> **Rule:** In lo-fi wireframes, never use real images or styled typography. Use X-boxes and placeholder lines. The goal is structure, not aesthetics. Introducing visual polish too early locks in decisions before the layout has been validated.

---

### 3.3 The Grid System

Web layouts are built on **grids** — invisible columns that align content consistently across the page. *Mrantinkovic et al. (2020)* identify the grid as a fundamental tool of layout design, applicable to both print and digital media.

**Common grid systems:**

| Grid | Columns | Common Use |
|---|---|---|
| **12-column** | 12 | Desktop — most flexible; supports 2, 3, 4, and 6-column layouts |
| **8-column** | 8 | Tablet layouts |
| **4-column** | 4 | Mobile layouts |

**Grid terminology:**
- **Column** — the vertical division of the layout
- **Gutter** — the space between columns
- **Margin** — the space between the content and the edge of the screen

In paper wireframing, a precise grid is not required — but column awareness is. Before placing any element, ask: *is this a full-width element, a half-width element, or a one-third element?*

---

### 3.4 Above the Fold

**The fold** is the bottom edge of the visible screen before the user scrolls. Content above the fold is seen immediately. Content below requires deliberate action from the user.

**Above the fold must contain:**
- The brand identity (logo or name)
- A clear statement of what the page or site is about
- The primary call to action
- Navigation to key sections

> **Common Mistake:** Placing a full-screen decorative image with no informational content above the fold. This forces users to scroll before they understand what the site offers — a critical failure in UX *(Mrantinkovic et al., 2020)*.

---

### 3.5 Spacing and Proximity

Students who completed the Design Principles module will recognize **proximity** as a core principle of layout. In wireframing, proximity is applied through deliberate **spacing** — the visible gap between elements.

- Elements that belong together are placed close together
- Elements that are separate are divided by whitespace or a divider
- Consistent spacing creates rhythm and reduces cognitive load

**Spacing scale (common convention):**
```
4px → 8px → 16px → 24px → 32px → 48px → 64px → 96px
```

Each step doubles. In paper wireframes, represent spacing by the visible gap between elements — be deliberate, not random. Inconsistent spacing signals an unplanned layout.

## PART 4: VISUAL HIERARCHY IN WIREFRAMES (20 minutes)

> This part applies Visual Hierarchy principles — covered in the Hierarchy module — specifically to web wireframe contexts. The six tools of hierarchy are not re-explained here; they are applied to a new medium.

### 4.1 Hierarchy Without Color or Typography

In a lo-fi wireframe, color and typography are stripped away. Hierarchy must be communicated through structural means alone. *Mrantinkovic et al. (2020)* note that a layout's hierarchy should be legible even before any visual styling is applied — if the structure requires color or typography to communicate priority, the layout itself is weak.

**Hierarchy tools available in a lo-fi wireframe:**

| Tool | How It Works |
|---|---|
| **Size** | Larger boxes signal more important content |
| **Position** | Top-left to bottom-right reading order (F-pattern and Z-pattern) |
| **Weight** | Thick lines represent headings; thin lines represent body text |
| **Whitespace** | Generous space around an element elevates its importance |
| **Contrast** | Filled boxes (dark) draw the eye before outlined boxes (light) |

Before finalizing any wireframe, ask: *where does the eye go first, second, and third?* If the answer is unclear, the hierarchy has not been resolved.

---

### 4.2 The F-Pattern and Z-Pattern

Eye-tracking research shows that users scan web pages in predictable patterns based on the type of content presented.

**F-Pattern** — common on text-heavy pages (articles, search results, product listings):
```
█████████████████████  ← Full first line read
█████████████          ← Partial second line
████                   ← Left edge scanned vertically
████
████
```

**Z-Pattern** — common on minimal, visual pages (landing pages, homepages):
```
█ ─ ─ ─ ─ ─ ─ ─ ─ ─ █  ← Top left to top right
              ↙
█ ─ ─ ─ ─ ─ ─ ─ ─ ─ █  ← Bottom left to bottom right
```

**Application in wireframing:**
- Place the logo top-left — both F and Z patterns begin there
- Place the primary CTA at the end of the Z diagonal or top-right
- Place the most important text in the first two lines of the F
- Do not place critical content in the bottom-right of a Z-pattern page — it is the last position seen

---

### 4.3 Call to Action (CTA) Hierarchy

Every page should have one **primary CTA** and at most one **secondary CTA**. More than two CTAs of equal visual weight creates decision paralysis — the user does not know what to do next.

| CTA Type | Visual Treatment in Wireframe | Example |
|---|---|---|
| **Primary** | Filled button, prominent size, isolated whitespace | "Get Started", "Order Now" |
| **Secondary** | Outlined button or text link, smaller | "Learn More", "See Menu" |
| **Tertiary** | Text link only, minimal visual weight | "Terms & Conditions" |

> **Rule:** Label every button with its actual text — never write "button" as a placeholder. The label is a design decision, not a detail to be decided later.

---

### 4.4 Content Chunking

**Chunking** is the practice of grouping related content into visually distinct blocks, reducing the cognitive effort required to process the page. *Mrantinkovic et al. (2020)* identify chunking as a direct application of the proximity principle to digital layout.

**Techniques:**
- **Card components** — each card is one self-contained chunk
- **Section backgrounds** — alternating light/dark sections separate content groups
- **Headings** — each heading introduces a new chunk
- **Dividers** — thin lines separate chunks within the same section

In a wireframe, chunking is represented by clearly bounded boxes with consistent internal spacing. A wireframe where all elements float freely with no grouping is a wireframe that will confuse developers and fail users.

## PART 5: UI PATTERNS & WEB CONVENTIONS (20 minutes)

### 5.1 What Are UI Patterns?

**UI patterns** are reusable solutions to common interface problems. They exist because users have learned to expect certain interactions in certain contexts through repeated exposure to the web. Deviating from an established pattern requires a user-tested reason — novelty for its own sake increases cognitive load and reduces usability *(Mrantinkovic et al., 2020)*.

> **Convention over invention:** Use established patterns unless you have a validated reason not to.

---

### 5.2 Navigation Patterns

| Pattern | Description | Best For |
|---|---|---|
| **Top navigation bar** | Horizontal links across the header | Websites with 4–7 primary sections |
| **Hamburger menu** | Icon that reveals a hidden menu | Mobile layouts, secondary navigation |
| **Sidebar navigation** | Vertical links on the left | Dashboards, documentation, admin panels |
| **Tab navigation** | Horizontal tabs that switch content | Filtered content, settings pages |
| **Breadcrumb** | Path trail showing current location | Deep hierarchies, e-commerce |
| **Footer navigation** | Secondary links at the bottom | Legal pages, sitemap, social links |

**Wireframing navigation:**
- Always show the navigation in its default (closed) state
- Add a separate wireframe for the open/expanded state if it changes the layout
- Label every navigation item with real text — "Nav Item" is not acceptable

---

### 5.3 Content Patterns

| Pattern | Description | Use Case |
|---|---|---|
| **Hero section** | Full-width banner with headline + CTA | Homepages, landing pages |
| **Card grid** | Repeating cards in a grid layout | Products, articles, team members |
| **Feature list** | Icon + heading + short description, repeated | Services, benefits, features |
| **Testimonial** | Quote + name + avatar | Trust-building sections |
| **FAQ accordion** | Question that expands to reveal answer | Support pages, product pages |
| **Modal / Overlay** | Content that appears over the page | Confirmations, alerts, quick forms |
| **Carousel / Slider** | Horizontally scrolling content | Featured items, image galleries |

> **Carousel Warning:** Carousels are one of the most misused patterns in web design. Users rarely interact past the first slide. Only use a carousel when content is genuinely sequential and equally important — not as a way to avoid making a hierarchy decision.

---

### 5.4 Form Patterns

Forms are among the most critical UI elements — they are where users take action. Poor form design is one of the leading causes of page abandonment.

**Form wireframing rules:**
- Every input field must have a visible label **above** the field — not inside it as placeholder-only text
- Group related fields together (e.g., First Name + Last Name on the same row)
- The submit button must be clearly the primary CTA
- Show error states and success states in separate wireframe annotations
- Never use more fields than necessary — every additional field reduces completion rate

**Standard form components:**
```
Label
┌─────────────────────────────┐
│ Input field                 │
└─────────────────────────────┘

Label
┌─────────────────────────────┐
│ Textarea (multi-line)       │
│                             │
└─────────────────────────────┘

☐ Checkbox label
◉ Radio option A
○ Radio option B

▼ Dropdown label

[ Primary CTA Button ]
```

---

### 5.5 Responsive Considerations

Web pages are viewed on screens of vastly different sizes. A wireframe that only considers desktop is an incomplete wireframe. *Mrantinkovic et al. (2020)* identify responsive design as a fundamental requirement of modern digital graphic design.

**The three primary breakpoints:**

| Breakpoint | Width | Layout |
|---|---|---|
| **Mobile** | 320px – 767px | Single column, stacked content |
| **Tablet** | 768px – 1023px | 2-column, some stacking |
| **Desktop** | 1024px+ | Full multi-column layout |

**Responsive wireframing rules:**
- Sketch at least a mobile and desktop version of every key page
- Navigation collapses to a hamburger menu on mobile
- Multi-column card grids stack to a single column on mobile
- Touch targets (buttons, links) must be large enough to tap accurately on mobile
- The mobile wireframe is not a shrunken desktop — it is a re-prioritized layout

---

### 5.6 Annotation

Wireframes are communication tools — they are read by developers, clients, and other designers. **Annotations** explain what the wireframe cannot show visually.

**What to annotate:**
- Interaction behavior (e.g., "clicking this button opens a modal")
- Dynamic content (e.g., "this section pulls from the latest 3 blog posts")
- Conditional states (e.g., "this error message appears if the field is empty")
- Responsive behavior (e.g., "this 3-column grid becomes 1 column on mobile")

**Annotation format:**
Use numbered callouts (①, ②, ③) pointing to elements, with a legend below or beside the wireframe. Every interactive element must be annotated.

## PART 6: ACTIVITY & SUMMARY (25 minutes)

### 6.1 Key Takeaways

1. **UI is what it looks like. UX is how it works.** Both are required for an effective web experience *(Mrantinkovic et al., 2020)*.
2. **Wireframing is the planning stage** — it happens before any visual design decisions. Never skip it.
3. **Lo-fi wireframes use boxes, lines, and labels** — no color, no real images, no styled typography. The goal is structure.
4. **Information Architecture** organizes content so users can find what they need in 3 clicks or fewer.
5. **User flows** map the path a user takes to complete a task — every page belongs to a flow.
6. **Hierarchy in wireframes** is communicated through size, position, weight, whitespace, and contrast — not color or typography.
7. **UI patterns** are reusable solutions to common problems. Use conventions before inventing new interactions.
8. **Forms** are the highest-friction UI element — every unnecessary field reduces completion rate.
9. **Every wireframe needs a mobile version** — mobile is not a shrunken desktop; it is a re-prioritized layout.
10. **Annotations** make wireframes readable by developers and clients — label all interactions, states, and dynamic content.

### 6.3 Effective vs. Ineffective Wireframes

| Feature | Effective | Ineffective |
|---|---|---|
| **Fidelity** | Appropriate to the stage (lo-fi for ideation) | Hi-fi too early — locks in decisions before validation |
| **Hierarchy** | Clear primary, secondary, tertiary elements | All elements equal weight — no visual priority |
| **Labels** | Real text on buttons and navigation | "Button", "Link", "Text here" as placeholders |
| **Annotation** | Interactions and states explained | No annotations — developer must guess behavior |
| **Mobile version** | Separate mobile wireframe provided | Desktop only — responsive behavior undefined |
| **CTA** | One clear primary action per page | Multiple competing CTAs of equal visual weight |
| **Content** | Based on a content inventory | Layout designed before content is defined |
| **Navigation** | Follows established patterns | Novel navigation with no user testing |
